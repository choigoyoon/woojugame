# 우주 블록 오락실 · UJU BLOCK ARCADE

네 가지 블록 액션과 나만의 아바타를 즐기는 모바일 Canvas 오락실. 로컬 게임 데이터·그림·합성 음향만 사용하며 외부 이미지, 음원, 폰트, 런타임 라이브러리, 계정 또는 결제가 필요 없다.

## 11월 25일 실제 플레이 개선

로비를 입체 오락기 네 대로 바꾸고, 아바타의 호흡·고개·눈깜빡임·팔꿈치·무릎 동작을 분리했다. 러너는 공중에서 다리를 접고, 배틀은 방향을 바꿀 때 대장이 기울고 뒷줄이 짧게 따라온다. 대장에게 장착 파츠를 표시하고 일반 대원의 왕관·날개 중첩을 줄였다. 로켓 팩은 정면에서도 보이도록 조정했다. 모드 이동은 입력을 지연시키지 않는 240ms 전환이며 줄어든 모션 설정을 따른다.

배틀의 양수 문은 작은 결과를 골라도 **표시된 인원이 합류**한다. 처음 18초는 사격·이동에 집중하며 이후 게이트 간격은 30초다. 세 진행 구간에서 적 편성이 달라지고, 새로 등장하는 보스 체력은 라운드별 600/900/1200으로 고정했다. 부대가 성장했다고 보스 체력을 함께 올리지 않는다. 기존 저장에 이미 등장한 보스의 체력은 그대로 복원한다. 이 변경만으로 경로 전략이나 연결 스토리를 완성한 것은 아니다.

상위 저장 버전 보호와 누적 시간 상한 결함도 수정했다. 새 연령 설정, 로비 기차·이야기 사건, 러너/광장 구조 개편, 독립 백업·계단 이어하기는 남아 있다. 실제 검사와 제한은 [이번 변경 검증 기록](docs/POLISH_2026_11_25.md)을 참고한다.

## 게임 설계 우선순위

기획 기준은 **게임 70%·교육 30%**다. 아이가 즐겁게 조작하고 탐험하면서 수·말·기억·계획·기다림을 실제 선택에 활용하도록 만든다. 이 비율은 문제풀이 시간 할당이 아니며, 게임 속 성적을 생활 속 성장의 증거로 단정하지 않는다.

[설계 재검토](PLAN.md#설계-재검토-아직-충분하지-않은-부분과-제작-중단-조건)에서는 현재 기획의 반복 선택·겉모양 분기·연령 축 결합·제작량 과소평가를 미해결 위험으로 명시했다. 첫 지역의 실제 입력·다른 공략·세계 변화·다음 날 복귀를 검증하기 전에는 새 책/기능 수를 늘려 완성도를 주장하지 않는다. 연령별 수치와 장기 분량은 여전히 검증 전 가설이다.

기본 액션만으로도 다시 하고 싶은 게임을 먼저 만든다. 수·말·기억은 전투, 탐험, 수집, 선택에 자연스럽게 쓰이게 한다. 현재의 반복 수식 게이트와 상시 문장 슬롯은 이 기준으로 재설계할 대상이다. ‘정답을 맞혀야 재미있는 구간이 열린다’를 핵심 진행 구조로 삼지 않는다. 이 항목은 후속 설계 방향이며 현재 네 모드가 이미 재설계됐다는 뜻은 아니다.

최신 [연령 선택·난이도·이야기 경험 설계](docs/AGE_DESIGN.md)는 **6~7세 / 8~9세 / 10~12세 / 13세 이상**의 시작 설정과 나중에 정하기를 제공하는 계획이다. 액션·수량·말·기억·계획·이야기 정보의 여섯 축을 따로 조절하고, 같은 나이의 숙련 차이를 반영한다. 예를 들어 조작이 능숙한 8세는 고급 경로와 쉬운 읽기 지원을 함께 사용할 수 있다. 연령으로 자산·모드·완전한 엔딩을 제한하지 않는다. **현재 앱에는 연령 선택과 이 설정 기능이 아직 없다.**

최신 [연결 스토리 — 사라진 마지막 칸](docs/STORY.md)은 네 지역의 12개 사건, 사건별 네 모드 해결 경로, 도구의 다른 쓰임, 돌아갈 이유와 엔딩 뒤 네 후일담을 정한다. 이야기 진행은 사건 단위이며, 한 모드만 골라도 진행할 수 있다. 기본 48코스·선택 16코스는 제작 목록으로 유지한다. **스토리와 개편 코스는 미구현**이다. 이 설계와 위에 기록한 로비·동작 개선을 구분한다.

[인물·사건 보강](docs/STORY.md#story-depth)에는 역에 모든 것을 모으려는 루프, 친구들과 함께 놀고 싶은 코코, 무대를 안전하게 옮기는 볼트의 서로 다른 목적을 넣었다. 출발/도착 표시와 별 도장의 의미가 뒤에서 달라지고, 아이가 선택한 경로와 축제 방식이 실제 세계에 남는다. 핵심 인과관계는 모든 연령에 공통으로 보여 주며 설명량·선택 부담을 조절한다.

최신 [장기 보존·성장 설계](docs/LONG_TERM.md)는 **다음 날 이어 하고 몇 년 동안 내 세계가 쌓이는 게임**을 목표로 한다. 네 모드의 안전한 이어하기, 보호자 백업 파일·기기 이전, 업데이트 시 자산 보존을 먼저 만든다. 첫 이야기는 첫 책이며 후속 모험과 오락실 증축으로 확장한다. 현재 저장 결함 보강 **L0가 새 콘텐츠보다 우선**한다. 상위 버전 보호·지표 상한 보정은 반영했고, 신규 저장 구조·독립 백업·이야기 책은 아직 미구현이다.

2026년 11월 21일 [스토리·구성 전체 재점검](PLAN.md#현재-스토리구성-재점검)에서 네 모드의 이야기 연결, 실제 수량과 배틀 보상의 불일치, 문장 정답에 종속된 질주, 지시 기억을 우회할 수 있는 광장 규칙, 성장과 콘텐츠 반복을 확인했다. ‘친구들과 장난감 우주 오락실을 다시 밝히는 모험’은 후속 이야기 제안이다. 저장 기반 이후의 첫 콘텐츠 대상은 배틀 한 판의 액션·수량 선택·성장·로비 변화 연결이며, 이번 재점검으로 게임 동작이 바뀐 것은 아니다.

2026년 11월 25일 [세부 제작안 D1~D10](PLAN.md#design-story)에 첫 3분, 배틀 한 판의 시간표/화력/보스, 계단·러너·광장의 실제 행동과 실수 복구, 기본 48·선택 16코스의 제작 목록, 보상·저장 이전·단계별 통과 조건을 구체화했다. 저장 기반 이후의 첫 콘텐츠 묶음은 배틀 한 판과 로비 기차다. 코스 목록과 수치는 **미구현 설계 초기안**이며 현재 분량·학습 효과·실기기 성능을 보장하지 않는다.

공통 상점은 기본 3종과 구매 가능한 파츠 **9종**(머리·몸통·등 각각 일반 2종 + 전설 1종)을 제공한다. 착용한 파츠의 색과 형태는 로비·계단·배틀 부대·러너·광장에 반영한다. 전설 파츠는 500코인과 보호자 PIN을 모두 확인한다.

보호자 센터에는 곱셈 진입 게이트, PIN 변경, 소리/진동 설정, 누적 플레이 시간·브레이크 성공률·연산 정답률·완성 문장·심부름 성공률이 있다. PWA 설치와 오프라인 재실행, 버전별 앱 셸 캐시, 명시적인 업데이트 적용을 지원한다.

배틀 첫 구역은 약 7분의 전투 분량이다. 러너·광장은 반복 가능한 진행을 제공하지만 **2~4시간의 독립 콘텐츠를 확보한 상태는 아니다**. 과거 `8구역 × 4게임 × 3라운드` 산식은 제작량 가설로 보류하고, 새 지형·행동·선택을 갖춘 실제 라운드 목록과 플레이 시간으로 분량을 검증한다. 4시간 규칙 반복 검사는 4시간치 새 콘텐츠나 실기기에서의 재미·발열 검증을 뜻하지 않는다.

## 실행과 조작

Node.js 20 이상. 실행용 패키지 설치는 필요 없다.

```sh
npm run dev
# GitHub Pages와 같은 경로로 확인
npm run dev -- --base /woojugame/
```

기본 주소는 `http://localhost:3000`. 같은 와이파이의 휴대폰에서는 `http://컴퓨터의-LAN-IP:3000`으로 실행한다. 설치·서비스 워커는 HTTPS 또는 localhost에서 확인한다.

- 로비: 네 카트리지, 상단 아바타 상점, 하단 보호자 버튼.
- 계단: 왼쪽 방향 전환, 오른쪽 오르기. 키보드 `←`/`Z`, `↑`/`→`/`X`/`Space`.
- 배틀: 화면 드래그 또는 `←`/`A`, `→`/`D`. 클리어 뒤 무기 카드를 선택해야 다음 라운드가 시작된다.
- 러너: 큰 점프 버튼 또는 `Space`/`↑`/`X`. 길게 누르면 높이 뛴다. 순서에 맞는 낱말을 머리로 맞히고, 다른 낱말은 물음표와 함께 다시 기회를 준다.
- 광장: 출동 뒤 화면을 누른 위치에서 드래그한다. 방향키/WASD도 지원한다. 가방이 차면 대장에게 돌아간다. 음표 버튼으로 목표를 다시 듣고 볼 수 있다. 유혹 물건을 집으면 코인을 잃지 않고 같은 미션을 다시 시작한다.
- 홈: 마지막 게임 입력 후 800ms 이상 지나고 누르고 있는 손가락/키가 없을 때 이동한다. 상점/보호자 화면에서는 바로 돌아갈 수 있다.

720×1280 중앙 9:16 FIT, 상하 `max(48px, safe-area-inset)`를 모든 화면에 적용한다. 화면 회전·폴드 크기 변경 시 눌린 입력을 해제한다. 화면 잠금·다른 탭·백그라운드에서는 게임과 소리를 멈춘다.

## 안드로이드 프레임 대응

안드로이드 공통 목표와 렌더링 상한은 **60fps**다. 90·120Hz 화면에서도 RAF의 그리기 시점을 골라 초당 약 60회 그린다. 이동·연사·판정은 실제 경과 시간을 사용하고 터치 입력은 즉시 처리한다. 실제 달성 프레임은 기기 성능·절전·발열에 따른다.

렌더링 부하가 지속되면 내부 픽셀 밀도를 100% → 87.5% → 75%로 낮춘다(DPR 상한 2, 하한 1). 여유가 15초 이상 유지되면 단계적으로 복원한다. 최대 조정 시 픽셀 수는 약 44% 줄어든다. 버튼 크기·터치 좌표·게임 난이도는 바꾸지 않으며, 전환 중 누른 조작도 유지한다. 시작/복귀 직후나 일회성 지연에 과민하게 반응하지 않도록 대기·히스테리시스를 적용한다.

`?debug`로 실행하면 개발자 도구의 `__uju.snapshot().performance`에서 실제 렌더링 평균, 관측 렌더링 주기, JS 작업 시간, 누락 비율, 해상도 배율을 볼 수 있다. 관측 주기는 기기 패널 사양을 식별하는 값이 아니다. 검증과 한계는 [프레임 최적화 기록](docs/FRAME_RATE_VALIDATION.md)에 정리한다.

## 판정과 시간

- 실제 프레임 시간은 최대 50ms. 배틀·러너·광장 물리는 고정 5ms 틱과 나머지 시간 누적으로 처리한다. 기기 주사율에 따라 이동·발사·타이머 속도를 바꾸지 않는다. 계단 타이머는 정확한 이벤트 경계를 소비한다.
- 유해 접촉 반경은 시각적 기준의 85%, 긍정 획득 반경은 120%. 배틀의 중앙 경계 0.08 안에서는 큰 결과 쪽을 우선한다. 보스의 표시된 공격 영역 가장자리에도 여유를 준다.
- 점프 착지·계단 휘청 회복에는 100ms 입력 버퍼를 적용한다. 브레이크의 빨간 본 판정 입력은 지연하지 않고 즉시 실패 처리한다. 일시정지·회전 시 선입력을 지운다.
- 일반 계단 1코인, 10콤보마다 +5, 브레이크 성공 15, 그림 다리 50. 배틀 보스 60과 최초 라운드 보너스 40/60/100. 낱말 5, 문장 완성 30, 광장 배달 50.
- 배틀 첫 구역은 10 이내 연산, 이후 최근 안정된 선택 10회로 난이도를 조절한다. 입력 없는 통과와 마지막 순간 차선 변경은 적응 난이도와 보호자 연산 통계에서 제외한다.
- 총알·적·게이트·낱말·코인·광장 물건·방해물은 고정 용량 풀에서 재사용한다. 계단 발판·스프링·이펙트와 부대 걷기 프레임도 재사용한다. 효과음 20성부, 음악 24성부, 해제 중인 음원 4개로 제한하고 노이즈·FM·피치 엔벨로프·컴프레서·소프트 리미터를 사용한다.

수치와 상한은 `js/config.js`, 구조와 이력은 [PLAN.md](PLAN.md)에 기록한다.

## 그래픽과 음악

공통 블록은 다단 플라스틱 재질·베벨·반사광·그림자를 Canvas에서 생성한다. 반복되는 블록, 부대원, 계단과 구름은 미리 그려 재사용한다. 수식과 낱말은 대비판과 외곽선 글자로 표시하고 큰 지갑 숫자는 폭에 맞춘다. 네 모드에 잔상·충격파·스파클·지갑으로 날아가는 베지어 코인을 적용한다. 보스·브레이크 성공·문장·배달 완료의 50ms 히트스톱은 화면만 잠깐 고정하므로 입력과 보상·타이머는 계속 정확히 처리한다. 줄어든 모션 설정에서는 히트스톱과 잔상을 끈다.

첫 터치로 오디오가 활성화되면 로비와 각 게임의 서로 다른 16마디 곡을 베이스·코드·멜로디·드럼 4성부로 연주한다. 한 실행에서 실제 플레이를 15분 누적하면 템포가 72%로 느려지고 로우패스·잔잔한 FM 오르골 편곡으로 전환한다. 로비 대기와 백그라운드는 이 시간에 포함하지 않는다. 이 음악 전환은 강제 휴식 타이머와 별개다. 배경 전환과 소리 OFF는 예약 음원까지 해제한다.

## 저장과 보호자 센터

`localStorage` 프로필 v3는 기존 v1/v2 지갑을 이전한다. 코인·보유/장착·설정·통계·배틀/러너/광장 체크포인트를 저장한다. 보상과 그 보상의 전투 상태는 프레임 계산을 모두 마친 뒤 한 문서로 기록한다. 일반 진행은 약 1초 간격, 보상·구매·선택·화면 이탈은 즉시 기록한다. 강제 종료 시 마지막 일반 저장 이후의 1초 미만 위치 변화는 되돌아갈 수 있다. 계단 위치는 새 실행에서 시작점으로 돌아간다.

매 저장 시 같은 내용을 백업 키에도 기록한다. 기본 문서가 손상되면 백업을 복원하고, 특정 모드 체크포인트만 잘못됐으면 해당 모드만 다시 시작하면서 지갑을 보존한다. 저장 공간/권한이 부족하면 메모리에서 플레이를 계속하고 상점에 임시 보관 상태를 표시한다. 미지원 상위 저장 버전은 덮어쓰지 않도록 플레이를 차단한다. 브라우저 데이터 전체 삭제나 다른 기기로의 이전을 복구하는 클라우드 저장은 없다.

2026년 11월 25일 [저장 점검](docs/LONG_TERM.md#long-audit)에서 누적 시간이 약 277.8시간으로 잘리는 상한과, 미지원 상위 버전 저장을 현재 앱이 초기값으로 덮어쓰는 문제를 격리 재현했다. 이번 코드 변경에서 두 결함을 수정했다. 상위 버전은 기본 키와 백업 키 모두 확인해 덮어쓰기를 막고, 실행 중 발견 시 플레이를 멈춘다. 후보를 전부 검증한 뒤 프로필을 교체하며 시간/횟수는 코인 상한과 분리한다. 10년치 합성 시간의 복원 검사는 실제 10년 운영 검증을 뜻하지 않는다. 현재 같은 브라우저 안의 백업 키는 독립 백업이나 과거 정상본 이력이 아니다. 신규 이어하기·백업·업데이트 호환 검증은 [L0 구현 순서](docs/LONG_TERM.md#long-delivery)를 따른다.

초기 PIN은 `0808`이며 보호자 센터에서 곱셈 게이트를 통과한 뒤 새 PIN을 두 번 입력해 변경한다. 변경한 PIN은 무작위 소금값과 PBKDF2-SHA256 해시로 보관한다. PIN 5회 실패 시 30초 대기, 보호자 세션 5분 및 화면 이탈 시 재확인을 적용한다. 이 로컬 게이트는 실수 진입을 막는 장치이며 서버 인증이나 성인 신원 확인 서비스가 아니다.

통계는 해당 기기 안에서만 집계한다. 플레이 시간은 로비·보호자 창·배틀 결과·광장 출동 대기를 제외한다. 브레이크는 실제 성공/실패, 연산은 안정된 수동 선택, 문장은 완성 개수, 심부름은 실패/성공 라운드를 집계한다. 게임 실력·학습 효과에 대한 진단값으로 사용하지 않는다.

## PWA와 배포

배포는 **main 브랜치 루트 직접 서빙**을 유지한다. [Pages 설정](https://github.com/choigoyoon/woojugame/settings/pages)에서 **Deploy from a branch → main → /(root)**. [게임 실행](https://choigoyoon.github.io/woojugame/).

HTML·모듈·manifest·아이콘·서비스 워커는 모두 `./` 상대 경로다. manifest의 `scope`/`start_url`/`id`도 `./`, 세로·fullscreen 표시를 지정했다. 아이콘은 Canvas로 직접 생성한 192px, 512px, maskable 512px PNG이며, maskable의 주요 그림은 안전 원 안에 배치한다.

```sh
# 아이콘을 수정할 때만 (아래 브라우저 도구 설치 필요)
npm run icons
# 앱 셸 해시와 sw.js를 생성하고 별도 단일 HTML 내보내기
npm run build
```

`sw.js`는 모든 앱 파일 내용에서 계산한 버전으로 캐시를 생성한다. 첫 설치는 캐시와 제어권을 확보한 뒤 게임 모듈을 열어 이전 HTTP 캐시와 새 모듈이 섞이지 않게 한다. 앱 셸 전체 다운로드에 성공해야 설치되며, 부분 다운로드 실패 시 기존 캐시를 유지한다. 설치 이후에는 캐시 우선으로 네 모드가 오프라인 동작한다. 한국어 로컬 TTS가 없으면 합성 효과음과 그림으로 진행한다. 최초 다운로드와 새 버전 다운로드는 연결이 필요하다.

새 버전은 `저장하고 다시 열기`를 눌렀을 때 활성화한다. 기존 진행을 저장하고 새로 열며, 해당 프로젝트 경로의 이전 버전 캐시만 삭제한다. 첫 온라인 실행 후 Android 브라우저의 설치/홈 화면 추가 메뉴를 사용한다.

`npm run build` 후 `sw.js` 변경을 소스와 함께 커밋한다. 자동 테스트가 파일 내용과 캐시 버전 불일치를 검출한다. `.github/workflows/verify.yml`은 main/PR에서 규칙·터치 흐름·PWA 검증을 수행한다. 이 워크플로우는 **검증용**이며 Pages 빌드 배포 방식으로 전환하지 않는다. `dist/index.html`은 별도 확인용 단일 파일이고 PWA 배포 대상은 아니다.

## 검증

```sh
python3 -m pip install -r requirements-browser.txt
python3 -m playwright install chromium
npm run build
npm test
npm run test:production
npm run test:pwa
npm run test:browser
npm run test:campaign
npm run test:audio
npm run test:audit
npm run test:fuzz
# 다른 무거운 테스트와 동시에 실행하지 않는다
npm run test:performance
npm run test:render-workload
npm run test:frame-budget
```

`CHROMIUM_PATH`로 기존 Chromium 경로를 지정할 수 있다. 결과와 캡처는 Git에서 제외된 `test-results/arcade/`에 남긴다.

최신 결과: [안드로이드 프레임 최적화](docs/FRAME_RATE_VALIDATION.md). 이전 결과: [0.5 화면·오디오·성능 감사](docs/POLISH_VALIDATION.md). 이전 결과: [0.4 통합 검증](docs/PRODUCTION_VALIDATION.md), [하늘 항구](docs/HARBOR_VALIDATION.md), [초기 오락실](docs/ARCADE_VALIDATION.md), [계단 Phase 1](docs/PHASE1_VALIDATION.md).

브라우저 터치/해상도 에뮬레이션과 설치 가능성 검사는 실제 Android 홈 화면 설치·진동·한국어 TTS·발열·배터리·8세 유저 관찰을 대신하지 않는다. 자동 테스트와 수동 미검증 항목을 검증 기록에서 구분한다.
