# 우주 블록 오락실 — 다음 날과 몇 년 뒤에도 이어 하는 설계

2026년 11월 25일 · 장기 보존·성장·콘텐츠 운영안 v0.3 · 현재 구현 기준 `3840a34`.

사용자 요구는 **저장된 내 세계를 다음 날 이어 하고, 몇 년에 걸쳐 계속 놀 수 있는 게임**이다. 게임 70%·교육 30%, Android 60fps, 공통 코인·아바타, 오프라인 플레이를 유지한다. 2~4시간은 한 번의 콘텐츠 묶음을 평가하는 범위이고 제품의 수명이 아니다. [STORY.md](STORY.md)의 ‘사라진 마지막 칸’은 첫 번째 이야기 책으로 둔다.

**이 문서는 설계와 현재 저장 구현의 점검 결과다.** 아래 신규 저장소·백업·기기 이전·새 이야기 책·장기 성장 기능은 아직 구현하지 않았다. 몇 년간의 데이터 보존과 재미를 이미 보장한다고 표현하지 않는다. 제작 우선순위는 **L0 저장 안전성 → 첫 사건과 세계 저장 → 이어하기 경험 → 확장 콘텐츠 → 선택형 원격 백업**이다. 첫 콘텐츠 구현보다 저장 결함 보강이 선행한다.

읽는 순서: [현재 상태](#long-audit) → [다음 날 이어하기](#long-resume) → [백업과 업데이트](#long-storage) → [몇 년의 성장](#long-growth) → [이야기 확장](#long-content) → [구현·검증](#long-delivery).

## L1. 현재 저장은 어디까지 되는가

코드 대조와 격리된 메모리 저장소로 재현했다. 실제 사용자의 저장 데이터는 변경하지 않았다. 전체 브라우저/Android 재검증이나 수년 운영 검증을 수행한 결과는 아니다.

| 현재 코드/재현 결과 | 의미 | 장기 요구를 만족하려면 |
| --- | --- | --- |
| `Profile`의 코인 321을 저장하고 새 인스턴스에서 321 복원 | 같은 저장소가 남아 있는 일반 재시작은 지원 | 보유/장착·설정·진행·세계도 하나의 복구 가능한 프로필로 유지 |
| 배틀/러너/광장은 체크포인트가 있고, `Arcade`의 계단은 새 `Game`으로 시작 | 계단의 위치·현재 사건은 다음 실행에서 이어지지 않음 | 계단까지 네 모드의 체크포인트와 안전한 재개 구현 |
| 기본 키와 `.backup`에는 매번 동일한 최신 JSON을 씀 | 주 데이터만 손상된 일부 경우는 복구하지만 과거 정상본은 아님 | 이전 정상 세대 보관, 전체 검증 후 원자적 교체 |
| 두 키 모두 같은 브라우저의 `localStorage` | 앱/브라우저 데이터 전체 삭제·기기 분실·새 기기·다른 출처 주소에서 복구할 독립본 없음 | 보호자 백업 파일과 가져오기, 선택형 원격 백업 |
| 시간 통계도 코인과 같은 `999,999,999` 상한으로 정규화 | `playMs`가 약 **277.8시간**에서 멈춤. 366일의 밀리초를 주입해 실제 절삭 확인 | 시간·코인·횟수별 단위/범위 분리. 일생 기록을 코인 상한으로 자르지 않음 |
| 저장 버전 4, 코인 999인 가상 데이터를 현재 v3 앱에 입력한 뒤 `Arcade`를 생성하면 버전 3·코인 0으로 덮어씀 | 앞으로 업데이트한 뒤 구버전 탭/앱을 열면 새 저장을 잃을 위험 | 미지원 상위 버전을 발견하면 쓰기 금지. 초기값으로 저장하지 않음 |
| `Adventure.restore`는 모든 숫자에 일괄 `abs(value) <= 1e9` 제한 | 누적 시간이 긴 체크포인트를 손상으로 오판할 수 있음 | 한 코스의 시간과 생애 누적 지표 분리, 필드별 의미 검증 |
| 저장 불가 시 메모리에서 플레이 지속 | 그 실행에서는 보상이 보이나 앱 종료 뒤 없어질 수 있음 | ‘이 기기에 저장됨’과 ‘임시 플레이’를 구분하고 복구 선택 제공 |

관련 파일: [profile.js](../js/profile.js), [arcade.js](../js/arcade.js), [adventure.js](../js/adventure.js), [campaign.js](../js/campaign.js). 위 상한/상위 버전 문제는 신규 저장 설계의 출시 차단 항목이다. 이번 문서 작성으로 수정되었다고 표시하지 않는다.

## L2. 다음 날 앱을 열었을 때의 장면

첫 화면에는 어제의 아바타와 파츠, 코인, 바뀐 오락실이 그대로 있다. 상단에 **‘이어서 놀기’** 카드 하나와 기존 네 게임 카드를 함께 보여 준다. 마지막 장면의 작은 움직이는 그림, 게임 아이콘, ‘공장 지붕에서 기차를 기다리는 중’ 같은 한 줄만 표시한다. 긴 요약을 강제하지 않는다.

이어서 놀기를 누르면 복원된 안전 지점에서 시작한다. 공격 중에 종료했어도 즉시 맞지 않도록 위험 예고를 최소 0.5초 다시 보여 준다. 이전 손가락/키 입력은 모두 해제한다. 다른 게임을 골라도 진행 중인 코스를 지우지 않는다. 네 모드에 각각 한 개의 진행 중 실행을 보관하고, 어떤 것을 가장 최근에 했는지만 이어하기 카드에서 추천한다.

| 그만둔 순간 | 다음 실행에서 복원할 것 | 반복하면 안 되는 것 |
| --- | --- | --- |
| 계단 47칸, 돌풍 예고 직전 | 현재 칸·방향·안전 발판·사건 상태. 입력 큐는 비움 | 1칸으로 초기화, 이미 받은 코인 재지급 |
| 배틀 보스 장갑 두 개 해제 | 병력·무기·보스 HP/해제 부품·위험 예고·지원병 결과 | 병력에 맞춰 보스 HP 재산정, 지원병/처치 보상 중복 |
| 러너 높은 길, 질주 3초 남음 | 선택 경로·가장 가까운 안전 착지점·남은 질주/획득 상태 | 말 선택 다시 강제, 같은 코인/스티커 재지급 |
| 광장 부품 두 개 전달, 가방에 한 개 | 요청·배치·부분 전달·가방·친구 반응 | 전달 완료분 초기화, 같은 물건이 바닥과 가방에 동시에 존재 |
| 이야기 사건 해결 직후 | 사건/지역/도구/로비 변화, 결과 확인 상태 | 다음 장 잠김, 같은 세계 보상 중복 |
| 상점 구매/장착 뒤 | 코인 차감과 소유·장착을 함께 복원 | 돈만 사라지거나 파츠만 공짜로 중복 획득 |

일반 위치는 약 1초 간격, 획득·구매·경로 선택·부분 전달·사건 해결·화면 이탈은 즉시 저장하는 것을 기본으로 한다. **저장 완료로 확인된 결과**는 재실행에서 그대로 복원한다. 강제 종료가 마지막 일반 저장 직전에 발생하면 위치가 마지막 안전 저장 지점으로 돌아갈 수 있으며, 화면에 보인 모든 밀리초가 전원 차단에도 보존된다고 약속하지 않는다. 보상과 소비된 물건/사건 상태는 반드시 같은 저장에 들어간다.

며칠·몇 달 쉬었다 돌아와도 코인·파츠·친구·도구가 감소하지 않는다. 오래 쉬었다는 이유로 강제로 처음부터 시작시키지 않는다. 복귀 시에는 마지막 목적지 그림과 선택 가능한 짧은 조작 시범만 제공한다. 날짜는 요약과 백업 설명에 쓰고 이야기 진행 조건으로 쓰지 않는다.

## L3. 오래 남길 것과 매 판 다시 시작할 것

| 범위 | 보관하는 내용 | 새 이야기/새 버전이 왔을 때 |
| --- | --- | --- |
| 생애 프로필 | 코인, 보유/장착, 무기/이야기 도구, 설정, 지표 | 그대로 보존. 시즌 리셋·강제 환생 없음 |
| 내 오락실 | 구한 친구, 놀이 기구, 배치, 사진/그림 앨범, 선택한 무대 | 증축하거나 새 공간으로 연결. 과거 성취를 철거하지 않음 |
| 이야기 책 | 사건 해결, 지역, 선택, 본 장면, 후일담 | 책장에 보관. 새 책을 시작해도 지난 책 재방문 가능 |
| 코스 기록 | 최초 완료, 모드/지원/규칙별 최고 기록, 발견 스티커 | 규칙이 바뀌면 기록 범주를 나누고 과거 기록을 삭제하지 않음 |
| 진행 중 실행 | 모드별 1개 코스의 안전 체크포인트, 현재 보상 처리 상태 | 같은 규칙이면 재개, 불호환이면 보상은 보존하고 가까운 안전 경계로 이전 |
| 한 판 연출 | 총알·반동·화면 흔들림·대사 재생 위치·눌린 손가락 | 의미 있는 물리 상태만 복원. 일시 연출/입력은 안전하게 재시작 |

한 계정/프로필에 세계는 하나이고 네 게임이 공유한다. 새 기기에서 불러오는 것은 같은 프로필의 이전이며, 두 개의 지갑을 합쳐 코인을 두 배로 만드는 기능이 아니다. 여러 아이의 별도 프로필 지원은 후속 기능으로 구분하고 이번 요구를 이유로 이름·생년월일·학교 정보를 수집하지 않는다.

## L4. 세 겹의 보관과 복구

### 1차: 기기 안의 자동 저장

현재 localStorage v3를 새 저장 관리자로 이전한다. 여러 해의 코스/세계 기록과 정상본 이력을 위해 **IndexedDB 트랜잭션 기반 저장**을 목표로 한다. 계정 데이터, 체크포인트, 처리한 보상, 정상본 인덱스를 같은 트랜잭션에서 기록한다. 화면의 저장 표시는 트랜잭션 성공을 확인한 뒤 갱신한다. 단순히 변수 값이 바뀌었다고 저장 완료라고 표시하지 않는다.

시작할 때 원본을 먼저 보관하고 전체 검증/이전이 끝난 후보만 새 정본으로 활성화한다. 중간에 앱이 꺼지면 다음 실행에서 기존 정상본 또는 완료된 새 정본을 선택한다. 부분 필드만 바뀐 프로필을 정본으로 만들지 않는다. IndexedDB 사용 불가 시 기존 데이터는 보존하고 임시 플레이/복구 안내를 제공한다. 저장 엔진을 바꿨다는 이유만으로 브라우저 삭제나 분실에 견디는 것은 아니다.

정상 저장 이력 초기값은 최근 정상본 5개, 최근 7개 저장일의 마지막 정상본, 최근 4개 저장주의 마지막 정상본이다. 실제 저장이 있었던 날만 만들고 접속을 유도하지 않는다. 같은 revision은 중복 보관하지 않는다. 기록 교체는 새 정상본이 검증된 후 수행한다. 이 이력은 손상/실수 복구용이고 독립 외부 백업을 대체하지 않는다.

브라우저가 허용하면 영속 저장 권한을 요청하고 현재 허용 여부를 표시할 수 있다. 거부돼도 플레이를 막지 않는다. 권한 허용도 앱 삭제·사용자의 데이터 삭제·기기 분실을 막는 보증이 아니다.

### 2차: 보호자 백업 파일

보호자 센터에 **‘백업 파일 저장’ / ‘백업 불러오기’**를 만든다. 백업에는 프로필 식별자, 형식 버전, 콘텐츠/규칙 버전, revision, 저장 시각, 게임 진행과 무결성 검사용 해시가 들어간다. 이름은 `uju-backup-날짜-짧은ID`처럼 알아볼 수 있게 한다. 해시는 우연한 손상 탐지용이며 암호화나 부정 변경 방지로 소개하지 않는다.

불러오기는 현재 지갑·파츠·이야기 진행과 백업의 값을 먼저 비교해 보여 주고 보호자가 선택한다. 적용 직전에 현재 상태의 정상본을 따로 보관한다. 검증 실패·더 높은 미지원 버전·파일 읽기 실패에서는 원래 데이터를 그대로 둔다. 단순 코인 합산, 서로 다른 기록의 무조건 최대값 병합, 파일 생성 날짜가 최신이라는 이유만으로 덮어쓰기를 하지 않는다.

백업 파일에 서버 인증 토큰·보호자 PIN 평문/해시는 넣지 않는다. 같은 기기에 불러올 때 현재 보호자 설정을 유지하고, 새 기기는 보호자 설정을 새로 마친다. 4자리 로컬 PIN은 계정 비밀번호나 클라우드 인증 수단으로 사용하지 않는다. 이미 소유한 전설 파츠는 복원되며 새 구매는 기존 코인+PIN 규칙을 따른다.

브라우저가 파일을 기기의 어디에 보관했는지는 확인 가능한 안내만 한다. 백업 버튼을 눌렀다는 이유만으로 외부 저장소나 다른 기기에 안전하게 보관됐다고 표시하지 않는다. 파일 자체를 별도 위치에 보관하면 새 기기와 주소 변경 시에도 복원할 수 있다.

### 3차: 보호자 선택형 원격 백업

몇 년의 상용 운영에서 기기 분실·교체까지 자동 복구하려면 기기 밖의 사본이 필요하다. **보호자가 연결하는 선택형 계정/원격 백업**을 장기 표준으로 둔다. 현재 GitHub Pages는 정적 앱 배포이고 원격 저장 서버가 아니다. 제공자·계정·운영 비용·인증/삭제/복구 정책은 구현 단계에서 구체화하며, 이번 작업에서 서비스 계정을 만들거나 서버를 배포하지 않는다.

온라인이 되면 변경된 안정 상태를 동기화하고, 오프라인에서는 기기 안에 저장하여 그대로 플레이한다. 클라우드 실패 때문에 정상 기기 저장을 초기화하지 않는다. 사용자가 실제로 연결하기 전에는 ‘클라우드에 저장됨’ 표시를 만들지 않는다.

두 기기가 오프라인에서 따로 진행했다면 덮어쓰기 전에 충돌을 보존한다. 마지막으로 동기화한 revision과 각 분기의 보상/소비 이력을 비교하고, 자동으로 안전한 처리가 불가능하면 보호자에게 두 상태를 보여 선택하게 한다. 선택하지 않은 정상본도 복구용으로 남긴다. 코인은 소비가 있는 자원이므로 합계/최대값 병합을 사용하지 않는다. 원격 저장이 있더라도 백업 파일 내보내기를 유지한다.

### 아이와 보호자에게 보이는 저장 상태

아이에게는 작은 **저장 중 / 이 기기에 저장됨 / 저장 확인 필요** 아이콘만 보여 준다. 보호자에게는 기기 저장, 파일 백업, 원격 동기화의 최근 성공을 분리해 표시한다. 저장 실패 중 획득을 시각적으로 보여 주더라도 임시 상태임을 표시하고 ‘완전히 보관됐다’고 말하지 않는다. 경고를 게임 도중 매 프레임 팝업으로 반복하지 않는다.

## L5. 몇 년 동안 업데이트해도 기록이 남는 규칙

| 종류 | 별도 식별자 | 유지할 원칙 |
| --- | --- | --- |
| 데이터 모양 | `schemaVersion` | 순차 이전 함수와 과거 저장 fixture 보관. 미지원 상위 버전은 읽기/쓰기 차단 후 업데이트 안내 |
| 이야기/코스 내용 | `bookId`, `contentVersion`, `stageId`, `beatId` | ID는 표시 이름과 분리하고 재사용하지 않음. 다른 책의 같은 코스 번호와 충돌 금지 |
| 물리/판정/보상 | `rulesVersion` | 체크포인트 호환성을 확인하고, 기록은 같은 규칙끼리 비교 |
| 저장 순서 | `profileId`, `revision`, `writerId` | 기기 시계가 바뀌어도 최신 상태 판단을 날짜만으로 하지 않음 |
| 구매/획득 | 안정된 `partId`, `rewardId`, `transactionId` | 이름/모양 변경에도 소유권 보존. 재개·이전·중복 동기화로 보상 재지급 금지 |

첫 책의 기존 `battle.harbor.01` 등 ID는 바꾸지 않는다. 새 책부터 `skycity.battle.market.01` 같은 충돌 없는 ID를 사용한다. 책 메타데이터는 별도 참조로 추가한다. 기존 이야기 진행은 해당 책의 사건 집합으로 이전하되 첫 책 완료를 두 번 세지 않는다.

중단한 실행을 지원하는 규칙/콘텐츠가 기기에 있으면 그대로 재개한다. 규칙이 더 이상 호환되지 않으면 현재 지갑·보유·완료 사건·전달/해제된 목표를 유지한 채 정해 둔 안전 경계에서 재시작하고 이를 알린다. 다운로드하지 않은 책의 체크포인트를 가져왔을 때는 상태를 보관하고 콘텐츠를 받을 때까지 해당 실행만 대기시킨다. 다른 설치된 게임은 계속 할 수 있다.

알 수 없는 파츠나 과거 콘텐츠의 ID는 삭제하지 않고 보존 영역에 남긴다. 임시 기본 외형 표시와 실제 소유 데이터 삭제를 구분한다. 이전 탭이 새 프로필을 덮어쓰지 못하게 상위 버전 쓰기 방지와 단일 쓰기 소유권을 검증한다. 높은 버전 정본이 있으면 옛 백업이 읽힌다는 이유로 자동 교체하지 않는다.

서비스 워커가 앱 코드를 갱신하는 절차와 게임 저장 이전은 분리한다. 새 셸 검증 실패 시 기존 앱 셸을 유지하고, 데이터 이전 실패 시 정본을 보존한다. 이미 이전한 저장을 읽지 못하는 구버전 앱으로 자동 회귀하지 않는다. 모든 출시는 과거 v1/v2/v3와 직전 버전에서의 이전 경로를 검사한다.

### 저장 크기와 수치가 계속 늘 때

누적 플레이 시간은 밀리초 단위의 안전 정수로 관리하고 코인 상한을 사용하지 않는다. 한 코스의 `elapsedMs`와 생애 `playMs`를 분리한다. 코인·횟수·시간·좌표는 각각 의미에 맞는 범위를 검사한다. 장시간 플레이로 누적 값이 커졌다는 이유로 정상 체크포인트를 지우지 않는다.

매 총알·입력의 이력을 영구 저장하지 않는다. 활성 실행의 중복 방지 상태는 실행 종료 후 정산 기록으로 압축하고, 코스별 최고 기록·최초 완료·발견·이야기 선택은 유지한다. 대용량 디버그 로그는 게임 저장에 넣지 않는다. 초기 용량 목표는 활성 프로필 1MiB 안팎, 백업 가져오기 상한 8MiB이며 실제 3년 분량의 합성 기록으로 검증 후 조정한다. 오래됐다는 이유로 소유물·세계·완료 기록을 임의 삭제하지 않는다.

| 시간 규모 | 아이가 하고 싶은 일 | 계속 남는 변화 |

| 오늘 한 판 | 친구 구하기, 더 멋진 파괴, 높은 길 발견 | 코인, 발견, 안전 체크포인트 |

| 몇 주 | 첫 책 완주, 다른 공략·도구 길, 후일담 | 책장, 사진/그림 앨범, 놀이 기구·외형 |

지역·친구·도구·놀이 기구는 일회용 소모품이 아니다. 오래된 친구가 다음 책에서 새 일을 하고, 이전의 선택이 짧은 대사·소품·선택 길에 돌아온다. 엔딩을 볼 때마다 기존 오락실이 다시 부서져 같은 수리를 반복하게 하지 않는다. 새 이야기의 문제는 다른 장소·도구·역할에서 생긴다.

성장은 병력/적 체력의 끝없는 숫자 증가에만 맡기지 않는다. 새 무기는 공격 형태, 새 도구는 갈 수 있는 경로, 새 친구는 상호작용, 새 장식은 내 공간의 모습을 바꾼다. 무기 조합·고급 경로·선택 도전은 숙련된 아이에게 더 깊은 공략을 제공하고 기본 이야기는 도움을 받으며 진행할 수 있다.

날짜가 바뀌었다고 숙제를 생성하거나 출석을 놓쳤다고 도구/친구가 사라지지 않는다. 새 추천은 2~3개만 보여 주고 모두 무시해도 기존 놀이가 열린다. 몇 달 뒤 돌아온 아이에게는 ‘밀린 일’ 목록 대신 마지막 장면과 지금 할 수 있는 선택을 보여 준다.

## L7. 아이가 커지면서 달라지는 놀이

기본 입력을 아는 정도, 조준/점프 숙련, 수량 판단, 읽기 속도, 요청 기억은 서로 독립적이다. 나이만으로 한꺼번에 난도를 올리지 않는다. 생년월일 입력 없이도 아이/보호자가 지원과 도전 정도를 선택할 수 있게 한다.

최신 [AGE_DESIGN.md](AGE_DESIGN.md)에 **6~7/8~9/10~12/13세 이상**의 선택과 미선택, 여섯 축의 기본값·개별 조정·기능 노출을 구체화했다. 연령은 저장하는 선택 구간이지 능력 판정이 아니다. 기존 사용자의 미선택과 사용자 조정을 보존하고, 생일/새해 자동 난도 상승은 하지 않는다. 나이 설정은 언제든 바꾸되 현재 실행의 난도 스냅샷·친구·진행·첫 완료 보상은 유지한다. 파일 백업과 기기 이전에도 같은 설정을 포함한다.

| 초기 경험 | 더 익숙해졌을 때 | 오래 즐겼을 때의 선택 도전 |
| --- | --- | --- |
| 배럴을 맞혀 적 몇 개를 부숨 | 배럴 이동과 적 대형을 보고 파괴 순서를 선택 | 같은 자원으로 무기·경로를 달리해 더 좋은 공략 찾기 |
| 작은 지원병 두 묶음을 합침 | 합류/이탈/필요 수량을 실제 장면에서 비교 | 두 보급 경로의 이득과 비용을 비교. 수 범위는 별도로 조절 |
| 짧은 말과 한 행동 연결 | 인물·대상·행동이 다른 두 유효한 부탁 선택 | 앞 행동의 결과를 보고 다음 부탁을 계획. 읽기 부담은 음성/그림으로 지원 |
| 종류 1~2개의 물건 전달 | 여분을 남기고 운반 순서를 선택 | 경로·가방·부분 전달을 계획. 무조건 외울 개수만 늘리지 않음 |
| 예고를 보고 잠깐 기다림 | 서로 다른 장치의 예고를 구분 | 안전한 흐름과 빠른 흐름을 선택하고 스스로 속도 조절 |

게임 70%·교육 30%를 유지한다. ‘2학년이 됐으니 더 긴 계산 문제’ 같은 자동 교과 진도를 기본 목표로 두지 않는다. 새 수·말·계획 능력이 게임의 선택을 풍부하게 하는지 관찰하고, 실제 효과는 별도로 판단한다. 예전 지표와 새 행동 지표를 버전 없이 한 점수로 합치지 않는다.

## L8. 첫 엔딩 이후의 책장과 콘텐츠 운영

오락실에 **별빛 책장/우주 지도**가 생긴다. 현재 ‘사라진 마지막 칸’은 첫 책이다. 새 책은 독립적으로 시작·사건·마침표가 있는 추가 모험이고, 기존 친구와 도구가 돌아온다. 책을 완주해도 이전 책과 후일담을 다시 할 수 있다. 신규 책을 못 받았거나 오프라인이어도 이미 설치한 네 게임과 책은 계속 동작한다.

| 이야기 책의 후보 | 새로운 사건과 플레이 | 이전에 얻은 것의 새 쓰임 | 제작 상태 |
| --- | --- | --- | --- |
| 1. 사라진 마지막 칸 | 열차 추적·공장 탈출·무대의 정체·축제 | 첫 친구·자석 고리·바람핀·스프링 | 상세 설계, 미구현 |
| 2. 뒤집힌 구름 도시 | 움직이는 거리의 방향을 바꾸며 친구의 집 찾아가기 | 바람핀으로 거리의 흐름을 바꾸고 자석 고리로 이동점 연결 | 후보 개요 |
| 3. 소리가 길이 되는 바다 | 박자에 맞춰 켜지는 항로와 움직이는 배를 탐험 | 항구의 경적과 친구 악기가 길의 단서로 돌아옴. 빛/형태 단서도 항상 동등 제공 | 후보 개요 |
| 4. 도착하지 않는 우주 우편 | 주소가 엇갈린 물건을 운반하고 경로를 조합 | 지난 책의 친구가 수신인, 배달 순서에 따라 다른 장면 | 후보 개요 |
| 5. 우리가 만든 작은 행성 | 직접 놓은 발판·배럴·장치를 시험하고 고치기 | 모은 장난감으로 짧은 개인 코스 제작 | 장기 확장 후보, 별도 구현/검증 필요 |

처음부터 모든 책의 발매를 약속하지 않는다. **새 책 하나의 운영 후보 단위는 지역 2개·사건 6개·모드별 대체 경로**, 즉 기본 24코스이며 실제 생산/검수 비용을 먼저 측정한다. 작은 후일담은 승인된 행동/지형을 재조합해 만들되 새 책과 같은 분량으로 세지 않는다. 분기별 새 책은 운영 목표 후보이고 자동 발매 일정이 아니다. 첫 책과 추가 책 하나의 제작 속도를 확인한 뒤 주기를 정한다.

반복 도전은 저자가 검수한 구간·목표·공략의 조합으로 만든다. 씨드가 다르다고 모두 새 콘텐츠라고 표시하지 않는다. 변화는 적 대형, 접근 경로, 운반 목적, 도구 활용 중 하나씩 읽을 수 있게 주고 동일 조건 재도전도 남긴다. 익숙한 경로에서 더 능숙해지는 재미와 새 이야기를 발견하는 재미를 함께 제공한다.

새 책의 리소스는 버전과 해시가 있는 콘텐츠 묶음으로 관리한다. 네 기본 게임과 이미 받은 책은 오프라인에 남기고, 새 책은 연결됐을 때 명시적으로 받는다. 다운로드가 끝나지 않은 책을 시작 가능하게 보이지 않는다. 안드로이드 공간이 부족하면 보호자가 콘텐츠 파일을 정리할 수 있으나 진행·소유·책 기록은 따로 남긴다. 다시 받으면 그 기록에서 이어 한다.

몇 년 동안 새 내용을 공급하려면 실제 제작·호환 검증·배포·복구 운영이 필요하다. 현재 64코스를 반복시키거나 생성 씨드만 무한히 늘려 ‘몇 년치 재미 완성’이라고 주장하지 않는다. 콘텐츠 운영이 중단돼도 설치된 놀이와 외부 백업으로 보유 기록을 유지할 수 있는 구조를 목표로 한다.

현재 후속 책 목록은 운영 능력의 증거가 아니다. [PLAN의 설계 재검토](../PLAN.md#설계-재검토-아직-충분하지-않은-부분과-제작-중단-조건)에 따라 첫 경험·재도전·다음 날·일주일 뒤에 실제로 무엇을 다시 선택하는지 관찰하고, 첫 지역의 제작/수정/회귀 비용을 먼저 측정한다. 날짜가 지난 테스트와 실제 재방문의 재미를 구분한다. 첫 지역에서 다른 해법을 시도할 이유가 없으면 정기적인 새 책 공급으로만 그 문제를 덮지 않는다. 장기 목표는 유지하되 운영 인원·제작 속도·비용·보존 지원 범위가 정해지기 전 수년의 콘텐츠 공급을 확약하지 않는다.

## L9. 저장을 먼저 만드는 실행 순서

| 단계 | 해야 할 실제 작업 | 완료 판정 |
| --- | --- | --- |
| L0-A 현재 저장 보호 | 미지원 상위 버전 쓰기 금지, 읽기 전체 검증, 시간/횟수/코인 범위 분리 | 상위 저장에 어떤 초기화 쓰기도 없음. 3년/10년 합성 지표가 절삭되지 않음 |
| L0-B 네 모드 이어하기 | 계단 체크포인트, 안전 재개, 네 모드 상태/보상 일관 저장, 마지막 모드 | 다음 날짜·오프라인·강제 종료 뒤 모든 모드와 자산 복원, 중복 지급 없음 |
| L0-C 독립 백업 | 세대별 정상본, 보호자 파일 내보내기/가져오기, 실패 표시, 이전 롤백 | 빈 새 브라우저에 파일만으로 복구. 실패한 가져오기는 기존 상태 불변 |
| L1 세계의 영속성 | 연령 선택/공통 설정을 첫 사건·도구·로비 기차·이어하기에 연결 | 어제 만든 세계와 현재 목적이 다음 날 그대로 보임. 연령 변경으로 자산·진행·보상 원장 초기화 없음 |
| L2 첫 책과 책장 | STORY의 12사건/대체 경로·후일담, 책별 기록 | 한 모드만으로 첫 책 완주, 다른 책 도입 뒤 과거 기록 보존 |
| L3 추가 책 검증 | 새 책 하나, 콘텐츠 묶음·오프라인 설치·과거 버전 이전 | 첫 책 자산/기록을 유지한 채 새 내용과 구내용 재방문 가능 |
| L4 원격 복구 | 보호자 계정 연결, 동기화 충돌, 기기 교체·삭제·복구 정책 | 실제 두 기기/오프라인 분기/복원 검증. 실패 시 기기 정상본 보존 |

장기 저장 기반 L0는 기존 ‘배틀 한 판부터’ 순서보다 우선한다. 콘텐츠를 계속 만든 뒤 저장을 마지막에 붙이지 않는다. 어떤 단계도 문서 작성으로 완료 처리하지 않는다. 첫 출시의 정확한 지원 범위는 구현/검증된 항목만 표시한다.

## L10. 출시 전 반드시 남길 증거

- **하루 뒤/30일 뒤 재실행:** 시스템 날짜를 바꾸고 새 브라우저 프로세스에서 재개. 날짜가 지났다고 진행/코인이 바뀌지 않음. 날짜 이동만으로 수년 사용을 검증했다고 하지 않음.
- **3년/10년 합성 기록:** 여러 책의 완료·수집·구매·재도전·지표를 누적한 fixture로 범위·크기·이전 검사. 예: 3년 × 하루 2시간 = `7,884,000,000ms`가 그대로 보존돼야 함.
- **강제 종료 경계:** 보상 직전/직후, 거래 저장 도중, 부분 전달, 마지막 잠금, 로비 전환에서 프로세스 종료. 다시 받는 보상·사라지는 지갑·반쪽 구매가 없어야 함.
- **과거 버전과 미래 버전:** v1/v2/v3 및 이후 보관 fixture의 순차 이전, 중간 실패, 미지원 상위 버전/구버전 탭의 쓰기 차단.
- **독립 복구:** 원래 브라우저 저장이 없는 새 프로필에서 백업 파일로 복원. 부분 손상·잘린 파일·다른 프로필·크기 초과·미지원 콘텐츠는 기존 데이터 보존.
- **동시 기기:** 같은 기기 두 탭, 다른 기기 오프라인 분기, 시계가 거꾸로 바뀐 상황, 늦게 도착한 동기화의 충돌 처리.
- **운영/콘텐츠:** 새 책 다운로드 실패·공간 부족·캐시 제거·구내용 재설치. 미설치 콘텐츠 때문에 프로필 삭제나 다른 게임 차단이 없어야 함.
- **실제 경험:** Android에서 잠금/재부팅/설치 앱 종료 후 재개, 보호자의 백업/복원, 아이의 며칠 후 복귀를 관찰. 서버 동기화나 수년 실사용을 헤드리스 결과로 대신 표현하지 않음.

현재 확인 완료는 **L1의 저장 구현 점검과 재현**, 그리고 장기 요구의 문서화다. L0~L4의 신규 기능과 실제 장기 관찰은 미완료다.
