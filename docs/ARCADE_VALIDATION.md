# 우주 블록 오락실 0.2 / 0.2.1 검증 기록

검증일: 2026년 11월 20일. 범위는 공통 로비·프로필, 기존 계단 연출과 브레이크·그림 다리, 3D 다리 배틀 런이다. 모드 3·4와 파츠 구매·PIN·PWA는 후속 범위이며 이번 로비에서 잠금/준비 중으로 표시한다.

## 0.2.1 사격 반응·전투 변화 개선

사용자 피드백에 따라 숫자 게이트 규칙을 유지하고 사격과 전투 구성을 개선했다. 두 단계 배럴 균열·외피 파손·피해 숫자·연쇄 폭발·코인 흡수, 6초 폭주 연사, 세 가지 적 편대, 차선 예고 공격과 체력 절반의 보스 변화가 추가됐다. 합성 타격음은 재사용하는 노이즈 버퍼와 저음·금속음을 겹치며 기존 동시 음원 12개 상한을 유지한다.

- `npm test`: **40개 통과**. 연쇄 폭발의 중복 지급 방지, 무기 상자·격파 충전·폭주 종료/정지, 고정 차선 예고·회피·1회 감원·최소 1명·복귀 보호·보스 격파 해제, 편대 변화를 추가 검증했다.
- `python3 tests/browser_check.py --stress-seconds 60`: 공통 기능·저장·하위 경로·18개 화면 조합 재검증 통과. 실제 시간 **60.11초**, 게임 시간 **60.15초**, 드래그 **541회(9회/초)**, 평균 **59.3fps**, 보스 2회, 오류 0건. 최대 적 7·탄 60·파편 160·음원 12·화면 부대원 24개로 각 상한 이내였다.
- `python3 tests/battle_impact_check.py`: 실제 터치와 제어된 시간으로 첫 배럴 파손→연쇄 폭발→무기 상자→폭주→이동 편대→보스 경고·회피·분노·격파까지 진행했다. 백그라운드 중 공격 예고와 폭주 타이머가 멈추며 복귀 시 예고를 새로 부여하는지 확인했다. 실행 중 동작 줄이기 설정도 적용됐다. 오류 0건.
- 추가 이펙트 풀: 타격 표시 최대 24·입체 파편 40·날아가는 코인 24. 기능 검사의 실제 최대 사용은 5·40·9개였다.
- 화면 검토 후 연쇄/폭주 문구를 하단으로 옮겨 게이트 수식을 가리지 않게 했고, 체력 숫자는 피격 섬광 위에 그린다. 피해 숫자도 대상의 중앙에서 옆으로 분리했다.

재현 결과: `test-results/arcade/battle-impact-report.json`, `impact-*.png`. 실제 소리 포함 플레이 영상: `test-results/arcade/battle-impact-demo.mp4`. Chromium 에뮬레이션 결과이며 Android 실기기 성능·발열·아동 플레이 관찰은 아직 미실시다.

이하 내용은 0.2 최초 오락실 통합 시점의 검증 이력이다.

## 환경과 실행 방식

Linux, Node.js 24.22.1, Chromium 156.0.8078.79, Python Playwright. 모바일 터치·DPR 2를 에뮬레이션했다. 실제 안드로이드 기기를 사용한 결과는 아니다.

이번 브라우저 검증은 개발 서버를 `/woojugame/`에 마운트하고 **실제 HTTP로 index/CSS/14개 ES 모듈을 로드**했다. 모든 응답이 정상이고 외부 에셋 요청은 없었다. 별도 생성한 `dist/index.html`에서도 로비와 두 모드를 실행해 단일 파일 빌드와 소스 실행을 모두 확인했다. GitHub Pages의 실제 공개 배포 완료를 이 로컬 HTTP 결과로 대신하지 않는다.

## 규칙·상태·저장

`npm test`: 35개 통과.

- 공통 프로필: 두 모드의 지급 합계, 장착 정보 복사, 버전·값 검증, 손상 데이터 복구, 저장 차단·용량 오류 중 메모리 플레이.
- 홈·수명주기: 799/800ms 경계와 누르고 있는 입력 보호, 로비 왕복 상태 보존, 비활성 모드와 백그라운드 시간 정지.
- 프레임 시계: 입력 직후 이전 시각의 RAF가 도착해도 시간을 중복 누적하지 않으며, 복귀 후 오래 지난 시간을 따라잡지 않는다.
- 계단 회귀: 1코인·10콤보 5코인, 정확한 1초 휘청, 같은 프레임 200회 처리, 10,000계단 발판 객체 재사용, 탄성의 30/60/120Hz 일치, 상승 음계와 표정.
- 브레이크: 499/500ms 예고 경계, 본 판정 입력 실패, 1,999/2,000ms 성공 경계, 15코인 한 번 지급, 자동 5계단에 일반 보상 중복 없음, 복귀 시 예고 재시작.
- 퍼즐: 48→53 자동 이동의 마지막 착지 뒤 50계단 퍼즐, 예고 중 50계단 우선권, 직전 3계단 예약 제외, 네 상황의 재선택·정답·중복 입력 보호.
- 배틀: 수식 2,000쌍의 계산값과 부등 관계, 정답 위치/색 독립성, 정확한 부대 증가, 작은 부대 1명·큰 부대 최대 3명 감소 및 하한 1, 상대 이동을 포함한 탄 충돌, 화력 증가와 상한, 보스 보상·다음 웨이브.
- 배틀 규칙 20분 시뮬레이션: 다수 보스를 격파하며 탄·적·게이트·이벤트 큐 상한을 유지. 실제 장치에서 20분 렌더링·발열을 측정한 결과는 아니다.
- 소리: 중단 상태에서도 음원 최대 12개, 상황별 합성 대체음, 한국어 기기 내 음성 부재·API 오류 무시.

## 실제 시간 연속 드래그

실제 시간을 사용해 `python3 tests/browser_check.py --stress-seconds 180 --stress-hz 9`를 실행했다. 180초 동안 드래그 1,620회(초당 9회), 보스 8회 격파, 9구간 진입, 오류 0건이었다. 평균 55.0fps를 확인하고 부대원 그리기 비용을 줄였다.

최종 렌더러는 직접 그린 부대원 걷기 자세 16개를 Canvas 내부에 캐시한다. 외부 이미지 없이 최대 24명의 부대를 같은 모션으로 그리고, 장착 상태가 바뀌면 다시 생성한다. 탄·총구 불빛·피격·폭발은 매 프레임 갱신한다.

최종 코드에서 기능 검사 전체와 60초 연속 드래그를 다시 실행했다.

| 측정 | 최종 결과 |
| --- | --- |
| 실제 시간 / 게임 진행 시간 | 60.11초 / 60.15초 |
| 입력 | 드래그 541회, 초당 9.0회 |
| 평균 프레임 | 60.0fps |
| 진행 | 보스 2회 격파, 3구간, 부대 70명 |
| 최대 객체 수 | 적 3, 탄 45, 파편 160, 동시 음원 7, 화면 부대원 24 |

이는 이 환경의 headless Chromium 측정이다. 안드로이드 실기기 성능과 발열은 아래 체크리스트로 별도 확인한다.

## 결과 파일

- `test-results/arcade/browser-report.json`: 기능·해상도·모듈·연속 입력 결과.
- `test-results/arcade/browser-report-180.json`: 캐시 최적화 전 3분 연속 입력 원본 결과.
- `test-results/arcade/visual-report.json`: 기존 연출·네 상황·고도 배경 결과.

- `test-results/arcade/arcade-demo.mp4`: 로비 → 배틀의 게이트·부대 확대·보스 격파 → 로비 → 계단을 실제 조작한 영상. 합성 게임 소리를 함께 녹화했다.
- `dist/index.html`: 외부 에셋 없는 단일 파일. 소스 배포에는 필요하지 않다.
