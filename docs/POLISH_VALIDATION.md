# 0.5 화면·오디오·입력/성능 감사

검증일: 2026-11-20. Node.js 24, Linux Chromium, Playwright, `/woojugame/` 하위 경로. 배포는 main 브랜치 루트 직접 서빙을 유지한다. 이 기록은 아래 재현 가능한 장면과 신호의 결과이며 모든 기기·모든 픽셀·주관적 음질에 대한 무결점 보증은 아니다.

## 변경한 출력

- `material.js`와 `art.js`: 다단 플라스틱 그라데이션, 상단 베벨/광택, 측면 암부, 부드러운 접지 그림자. 블록 스프라이트 256개·색상 512개 상한. 계단의 구름·발판·버튼·HUD와 배틀의 바다·HUD는 실제 화면 밀도에 맞춘 Canvas 이미지로 재사용한다. Art 인스턴스의 레이어 캐시는 24개 이하이며 리사이즈 시 교체한다. 부대원 16프레임 스프라이트도 투시 후 가장 큰 표시 크기에 필요한 픽셀 밀도로 생성한다.
- `juice.js`: 네 모드 공통 잔상, 충격파, 스파클, 보상 코인의 베지어 지갑 비행. 코인 32·링 12·스파클 96·잔상 4개 상한. 잔상은 당시 아바타 모습을 재사용 Canvas에 저장한다. 보스·브레이크 성공·문장/배달 완료 시 50ms 화면 히트스톱. 물리·입력·보상 계산은 멈추지 않는다. reduced-motion에서는 히트스톱·잔상을 끈다.
- 수식과 낱말에 대비판/외곽선 글자를 적용했다. 9자리 지갑 숫자는 실제 글자 폭에 맞춰 축소한다. 효과는 상단 문장/미션 안내를 가리지 않도록 플레이 영역과 지갑 아이콘 주변으로 제한한다.
- `music.js`: 로비/계단/배틀/러너/광장 각각 다른 16마디 곡, 베이스·코드·멜로디·드럼 4성부. 모드별 108/128/142/136/112 BPM. 실제 활동 시간 15분 뒤 템포 72%, 저역 통과 1.6kHz와 부드러운 FM 오르골 편곡으로 전환한다. 로비/백그라운드는 활동 시간에서 제외한다.
- `audio.js`: 효과음과 음악 버스를 분리했다. 노이즈 버스트, ADSR, 피치 스윕, FM 코인, 보상 아르페지오를 합성한다. 컴프레서 뒤 소프트 리미터를 두고 효과음 20·음악 24·감쇠 중 음원 4개로 제한한다. 포화 시 감쇠 여유도 없으면 새 음원을 버려 연속 hard-cut을 피한다. 배경 진입 시 예약 음원까지 정지/분리한다.

## 화면 직접 검수

`python3 tests/visual_audit.py`는 실제 배포 렌더러를 격리된 결정적 모델 상태로 호출한다. 게임의 구매·정답·보상을 통과시켰다는 증거와 구분하며, 그 흐름은 별도의 trusted-touch 테스트로 확인한다.

| 화면 묶음 | 바형 412×915 | 폴드 768×1024 | 태블릿 1024×1366 |
| --- | --- | --- | --- |
| 로비·보호자 대시보드 | 2장 | 2장 | 2장 |
| 계단·슈퍼 스톱·그림 다리 | 3장 | 3장 | 3장 |
| 배틀 수식/총격·보스 | 2장 | 2장 | 2장 |
| 러너 낱말·황금 질주 | 2장 | 2장 | 2장 |
| 광장 이동·지시·배달 완료 | 3장 | 3장 | 3장 |
| 상점 9종 장착 모습 | 9장 | 9장 | 9장 |
| 최대 지갑 숫자·전체 뷰포트 | 5장 | 5장 | 5장 |

필수 63장 + 경계/전체 화면 15장 = 78장. 실제 PNG를 열어 글자 경계, 버튼, 파츠 배치와 중앙 레터박스를 확인했다. 확인 중 발견한 9자리 지갑 넘침, 조이스틱과 안내 문구 겹침, 계단 홈 버튼/점수판 테두리 겹침, 보상 코인의 상단 안내 침범과 밝은 배경에서 배틀 구역/보스 이름의 낮은 대비를 수정했다. 수정 화면을 재촬영해 확인했다. 캡처 범위에서 의도하지 않은 잘림/겹침은 발견되지 않았다. 플레이 중 아바타와 장애물의 자연스러운 가림, 일시적인 피격 플래시는 레이아웃 오류와 구분한다.

아티팩트: `test-results/arcade/visual-audit/manifest.json`, `{bar,fold,tablet}-*.png`, 검수 이미지의 SHA256을 기록한 `manual-review.json`. 최초 캡처 fixture의 DPR 누락도 고쳐 배포 렌더러와 같은 변환을 사용한다. 리사이즈 콜백이 fixture 위에 실제 앱의 일시정지 화면을 덮는 경쟁도 확인해 별도 Canvas로 분리하고 재촬영했다. 이러한 fixture 수정은 앱 오류로 집계하지 않는다.

## 실제 오디오 출력

`python3 tests/audio_audit.py`는 mock 대신 Chromium `OfflineAudioContext`로 배포 오디오 그래프와 시퀀서를 실행한다. 44.1kHz Float32 양 채널의 유한성/동일성을 확인하고 원본 샘플에서 수치를 계산한다. 검토용 WAV만 PCM16으로 내보낸다. 5곡 × 전체/4개 단독 성부 = 25건(전체 믹스는 16마디를 두 차례 완주하며 반복 이음새 포함, 단독 성부는 각각 4초), 과부하·오르골·배경 정지·빠른 모드 전환·효과음 묶음 5건, 총 30건이다.

| 실제 믹스 | RMS | Peak | 최대 인접 샘플 변화 |
| --- | ---: | ---: | ---: |
| 로비 | 0.02573 | 0.23253 | 0.03289 |
| 계단 | 0.02718 | 0.23531 | 0.01585 |
| 배틀 | 0.02629 | 0.20561 | 0.03088 |
| 러너 | 0.02882 | 0.23362 | 0.03133 |
| 광장 | 0.02505 | 0.24066 | 0.03120 |
| 연사/피격/폭발 과부하 | 0.14462 | 0.86221 | 0.05316 |
| 15분 이후 오르골 | 0.01939 | 0.10772 | 0.00271 |
| 0.4초 간격 모드 전환 | 0.03234 | 0.21644 | 0.03081 |
| 점프/획득/완성 등 효과음 | 0.06975 | 0.64429 | 0.11874 |

- 30건 모두 유한 샘플, Peak < 0.97, 최대 인접 변화 < 0.35. NaN과 기준 초과 0건.
- 전체 BGM 믹스의 시작/의도적 종료를 제외한 100ms 구간에서 RMS < 0.0001인 무음 구간 0건. 단독 악기와 개별 효과음의 악보상 쉼은 오류로 집계하지 않는다.
- 배경 진입 3초 이후 감쇠 여유를 둔 3.2초부터 Peak < 0.000001. 실제 실시간 컨텍스트도 `suspended`, 살아 있는 음원 노드 0개. 복귀 후 출력 재개.
- 모든 측정의 정리 후 음원 노드 0개. 음악·효과음·감쇠 음원 상한 준수.
- 파형 그래프 두 장을 직접 열어 신호 지속, 과부하 피크, 배경 진입 뒤 평탄한 무음과 확대 파형을 확인했다. 그래프는 10ms 구간 최솟값/최댓값과 RMS, 가장 큰 인접 변화 주변 10ms 확대 파형을 표시한다. 단순 다운샘플링으로 순간 피크를 숨기지 않는다.

아티팩트: `audio-audit/report.json`, 10개 WAV, `soundtracks-waveforms.png`, `safety-waveforms.png`. 인접 샘플 변화 기준은 불연속 신호를 찾는 정량 검사다. 스피커에서 들리는 모든 클릭/왜곡이나 음색의 좋고 나쁨을 판정하는 청취 테스트와 동일하지 않다. 브라우저 정책상 첫 사용자 터치 전에는 소리가 나지 않는다.

## 입력·메모리·프레임

시드 20261120, 48회 모드 왕복, 6,672회 CDP 터치 이벤트(두 손가락 이동/해제/취소 + 누른 상태에서 세 번째 손가락 홈 시도), 6회 페이지 재실행. 입력 소유권 잔류·가드 우회·저장 지갑/장착 불일치·JS 오류 0건. 렌더/음원 캐시 상한도 확인했다. 워밍업 후 강제 GC 시점의 유지 JS 힙 범위는 617,852바이트(약 0.62MB)였다. 이 유한 구간에서 지속적인 힙 증가 징후가 없었으며 모든 형태의 메모리 누수 부재를 수학적으로 증명한 것은 아니다.

OS가 빈 `changedTouches`로 취소해도 전체 `touches` 목록과 대조해 손가락을 해제하도록 보강했다. 취소가 키보드 입력까지 해제하지 않는 회귀 테스트도 추가했다.

성능 측정은 다른 무거운 검사와 분리하여 실제 RAF로 각 모드 25초를 측정한다. 초기에 계단 모드 34.1fps를 발견해 발판/구름/버튼/HUD 재질과 잔상 재사용을 추가했다. 계단 구름과 배틀 바다처럼 천천히 움직이는 배경은 20Hz로 갱신하고 매 RAF에 합성하며 캐릭터·입력·게임 물리는 기존 주기로 유지한다.

| 모드 | 평균 fps | p95 / p99 프레임(ms) | 50ms 초과 작업 |
| --- | ---: | ---: | ---: |
| stairs | 59.4 | 16.8 / 33.3 | 0 |
| battle (25초) | 59.28 | 16.7 / 33.3 | 0 |
| battle (최종 60초) | 58.92 | 16.8 / 33.3 | 0 |
| runner | 59.84 | 16.7 / 16.8 | 0 |
| plaza | 59.92 | 16.7 / 16.8 | 0 |

412×915 CSS, DPR 2, 실제 RAF에서 측정했다. 각 25초 모두 평균 57fps 이상·p95 < 20ms·p99 < 34ms 기준 통과. 일부 33.3ms 프레임은 남아 있으며 모든 프레임 16.7ms 이하라는 뜻은 아니다. 화면 해상도는 줄이지 않았다. 아티팩트: `polish-performance-report.json`. 이 호스트의 짧은 기준 측정이며 Android 장시간 발열/배터리 성능의 대체 자료가 아니다.

## 재현과 회귀

```sh
python3 -m pip install -r requirements-browser.txt
python3 -m playwright install chromium
npm run build
npm test
npm run test:production
npm run test:pwa
npm run test:audio
npm run test:audit
npm run test:fuzz
# 별도 단독 실행
npm run test:performance
python3 tests/polish_performance.py --seconds 60 --modes battle --output polish-performance-final-battle-60s.json
```

- `npm test`: 70/70 통과. 규칙·동일 시간 시뮬레이션·저장·오디오 정리·입력 취소·VFX 상한 포함.
- 실제 터치 통합: PIN 변경/이전 PIN 거부, 코인+PIN 중복 구매 방지, 모든 파츠 슬롯, 낱말 3연속→황금 변신, 광장 정확한 수거/배달, 36개 화면/회전/폴드 조합, 일시정지/복귀 통과.
- 최종 PWA: 34개 앱 셸 파일, 설치 가능성 오류 0, 브라우저 완전 종료 후 오프라인 네 모드 및 코인/파츠 복원, 손상된 주 저장본의 백업 복구, 실패 업데이트 유지/명시적 정상 교체 통과. 마지막 빌드 후 캐시 해시 테스트도 통과.
- 오디오 30건과 화면 78장 통과. 시각 검수는 자동 픽셀 판정과 구분해 위에 기록했다.
- 기존 계단/배틀 회귀: 18개 화면 조합, 두 손 입력·브레이크·그림 다리·게이트·보스 보상·무기 선택·단일 HTML 실행 통과. 60초 540회 연속 드래그에서 상태/상한 오류 0, 진행 시간 59.53초. 이 검사는 퍼징과 병행되어 평균 54.9fps였으므로 단독 프레임 측정과 구분한다. 글자 대비 수정 뒤 단독 25초는 58.53fps였다. 추가 60초 측정에서 56ms 장기 작업 1건을 발견해 부대원 스프라이트 밀도를 최적화했다. 최종 60.3초 재측정은 평균 58.92fps / p95 16.8ms / p99 33.3ms / 50ms 초과 작업 0건으로 통과했다(`polish-performance-final-battle-60s.json`).

GitHub Actions는 규칙·실제 터치·PWA·파형·스크린샷 생성·퍼징을 수행하고 결과 폴더를 업로드한다. 공유 CI 호스트의 성능 수치는 전용 기기 성능으로 취급하지 않으며 실시간 성능 검사는 별도 실행한다. 스크린샷 생성 자동화가 매 릴리스의 직접 시각 검수를 대체하지 않는다.

## 남아 있는 출시 확인

실제 Android의 홈 화면 설치, 오프라인 강제 종료, 스피커/이어폰 청취, 진동, 한국어 로컬 TTS, 발열·배터리·장시간 60fps, 8세 사용자 관찰은 실제 기기에서 별도로 기록해야 한다. 이번 자동 검증만으로 상용 출시 품질이나 모든 기기의 60fps를 인증하지 않는다. 온라인 Pages 확인 요청은 이 실행 환경의 CONNECT 프록시에서 HTTP 403으로 차단됐다. 따라서 원격 main 푸시 여부와 실제 Pages 게시 완료 여부를 구분하며, 라이브 사이트/Actions 완료를 검증했다고 표시하지 않는다.
