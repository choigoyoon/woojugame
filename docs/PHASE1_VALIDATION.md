# 우주 블록 런 Phase 1 검증 기록

검증일: 2026년 11월 20일. 대상은 준비 단계와 Phase 1 계단 액션이다. 브레이크·퍼즐·상점·PIN·저장·쿨다운·PWA는 설정값과 예약 상태만 있으며 실행 기능은 포함하지 않는다.

## 실행 결과물

- 개발 실행: 저장소 루트에서 `npm run dev`. Node.js 20 이상이며 런타임 패키지 설치는 필요하지 않다.
- 단일 파일 생성: `npm run build`로 `dist/index.html`을 만든다. CSS와 JavaScript를 모두 포함하며 외부 이미지·음원·라이브러리를 불러오지 않는다.
- 상세 실행 방법: [README](../README.md).

## 자동 검증 결과

환경은 Linux, Node.js 24.22.1, Chromium 156.0.8078.79, Python Playwright 1.62.0이다. 브라우저 검증은 단일 HTML을 메모리에 로드하고 터치와 모바일 뷰포트를 에뮬레이션했다.

| 검증 | 결과 |
| --- | --- |
| `npm test` | 11개 테스트 통과 |
| 일반 계단과 콤보 보상 | 계단당 1코인, 10콤보마다 5코인 추가 지급 확인 |
| 방향 실수 | 위치·코인 유지, 콤보만 0, 정확히 1,000ms 경과 후 조작 복귀 확인 |
| 같은 프레임의 연속 조작 | 렌더링을 끼우지 않은 200회 상승의 순서·보상 정확성 확인 |
| 발판 메모리 | 10,000계단 추가 진행 중 동일한 발판 객체 16개 재사용 확인 |
| 소리 중단 | `onended`가 오지 않는 중단 상태에서도 음원·게인 연결 수가 제한되고 일시정지 시 정리됨 |
| 개발 서버 | 실제 HTTP 요청으로 진입 HTML, CSS, 6개 ES 모듈의 응답과 MIME 확인 |
| GitHub Pages 상대 경로 | 진입 파일과 전체 ES 모듈이 `/woojugame/` 아래로 해석되는 회귀 테스트 통과 |
| 첫 터치 | 한 번의 조작·코인 지급, Web Audio 활성화, 호환 마우스 이벤트 중복 없음 |
| 동시 두 손 입력 | 하나의 `touchstart`에 들어온 방향 전환·오르기 두 입력이 순서대로 한 번씩 적용됨 |
| 터치 취소 | `touchcancel` 후 눌림 상태가 남지 않고 컨텍스트 메뉴가 차단됨 |
| 화면 생명주기 | `pagehide`·`pageshow` 신호로 휘청임 타이머·프레임 정지와 복귀 확인 |
| 후속 단계 비활성 | 50계단을 넘어 계속 진행해도 Phase 2·3 기능이나 예약 이벤트가 실행되지 않음 |

### 화면 크기

다음 CSS 뷰포트 6종에서 9:16 비율과 중앙 정렬, 상하 최소 48px 여백, 화면 하단 22%의 두 버튼 히트박스를 확인했다. 기기 배율은 2다.

| 뷰포트 | 용도 | 결과 |
| --- | --- | --- |
| 360×800 | 좁은 세로 화면 | 통과 |
| 412×915 | 일반 세로 화면 | 통과 |
| 344×882 | 긴 폴드 외부 화면 비율 | 통과 |
| 768×1024 | 폴드 펼침·태블릿 비율 | 통과 |
| 1024×1366 | 큰 태블릿 비율 | 통과 |
| 915×412 | 가로 회전 후 세로 게임 유지 | 통과 |

Canvas 캡처에서 캐릭터·발판·코인·두 버튼의 배치를 확인했다. 위 결과는 실제 Galaxy 모델이나 안드로이드 OS에서 수행한 테스트가 아니다.

### 3분 연속 터치

최종 구현에서 `python3 tests/browser_check.py --stress-seconds 180`을 실행했다.

- 실행 시간 180초, 초당 8회 속도의 실제 브라우저 터치 이벤트 총 1,440회.
- 입력 1,440회 수집·처리, 누락·중복·의도하지 않은 차단 0회.
- 930계단과 1,395코인으로 계산 결과 일치: `930 + 93 × 5`.
- 발판 객체 16개 유지. 파편 96개, 동시 음원 12개 상한 확인.
- 평균 렌더링 60.0fps, JavaScript 오류 0건, 외부 네트워크 요청 0건, 화면 확대 없음.

위 프레임 수치는 이 Linux 에뮬레이션 환경의 측정값이다. 메모리에 HTML을 넣은 실행의 준비 시점은 약 101ms였으며, 휴대폰의 최초 HTTP 로드나 1초 진입 목표를 검증한 수치는 아니다. 난수로 계단 방향을 생성하므로 반복 실행의 계단 수는 달라질 수 있고, 입력 수와 보상 공식의 일치 여부를 검사한다.

브라우저 결과 JSON과 캡처는 재실행 시 `test-results/`에 생성된다. 테스트 명령과 의존성 준비 방법은 [README](../README.md)를 따른다.

## 실제 안드로이드에서 남은 확인

- [ ] 기준 기기 모델, Android 버전, 브라우저 버전을 기록한다.
- [ ] 실제 휴대폰에서 3분 이상 플레이하며 화면 배치·발열·끊김·효과음 크기를 확인한다.
- [ ] 양손으로 초당 8회 이상 연타할 때 입력 누락·줌·팝업이 없는지 확인한다.
- [ ] 홈 화면 이동, 화면 잠금·해제, 회전과 폴드 펼침·접힘 후 조작·소리를 확인한다.
- [ ] 캐시된 재실행과 최초 온라인 실행 시간을 각각 측정한다.
- [ ] 아이가 설명 없이 두 버튼과 방향을 이해하는지 관찰한다.

공유 클라우드 미리보기는 릴레이 연결 시간 초과와 브라우저 시작 오류로 열리지 않았다. 실기기 확인용 배포는 GitHub Pages의 `main` 브랜치 루트 직접 서빙 방식으로 준비했으며, 활성화 절차는 [README](../README.md)를 따른다. `/woojugame/` 하위 경로에서 진입 HTML·CSS·6개 ES 모듈의 HTTP 200 응답을 임시 정적 서버로 확인했다. 현재 코인·진행도는 메모리에서만 유지되므로 새로고침하면 초기화된다.
